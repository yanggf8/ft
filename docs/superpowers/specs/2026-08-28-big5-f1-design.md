## 2. 架構（沿用現行單 Rust stack 慣例）

| Crate | 本切片職責 |
|---|---|
| `crates/domain/big5`（ft-big5，現為 placeholder） | 純邏輯、無 IO、native+wasm32 可編：`validate`（15 題、整數 1–5）、`score`（反向翻轉＋0–100 換算）、`detect_careless`（三訊號）、常模 re-export（`NORMS`/`SOURCE` 權威在 ft-schema）。反向題配置為常數 |
| `crates/schema`（ft-schema） | wire 型別先行（§4）**＋IPIP-15 題目與 N=738 常模靜態資產（items 模組）**——web 禁依賴 domain，共用靜態資料必須放這裡；合約即測試，前後端唯一真相 |
| `crates/api`（fortunet-api） | 新路由模組 `routes/personality.rs`；計分在 server（**web 禁止依賴 domain/big5**，rev.4 Part II §2 硬性要求，CI 以 `cargo tree -p ft-web` 檢查）；套 per-IP rate limit（對齊 auth 現行機制） |
| `crates/web` | `/personality` 路由（Protected）＋ Home 入口卡；僅依賴 ft-schema::api |

體積影響：ft-big5 純常數與算術，無外部依賴，對 wasm 預算可忽略。

## 3. D1

`scripts/schema.sql` 為唯一權威，本切片只加一張表（D1 無約束慣例：無 FK/CHECK，應用層驗證）：

```sql
CREATE TABLE IF NOT EXISTS personality_profiles (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  ipip_answers TEXT,                 -- JSON [15] int 1–5；skipped 記錄為 null
  ocean_measured TEXT,               -- JSON 五維 0–100；僅 complete 有值
  measurement_status TEXT NOT NULL,  -- 'complete' | 'careless_suspected' | 'skipped_prior_only'
  item_duration_ms INTEGER,          -- 總作答時長 ms（client 量測上送）
  created_at TEXT NOT NULL           -- 一律由 app 寫 clock::now_iso()（ISO）；不用 DEFAULT
                                     -- datetime('now')：空格格式與 ISO 字典序不一致，混用會亂序
);
```

**不建** `situation_checks`／`predictions`——F5 的 predictions 須按四段結構（`tendency/trigger/forecast/experiment`）重新設計，現在建立是猜測；D1 無約束慣例下後續建表零痛。

## 4. API 契約（wire shape 先落 ft-schema）

### POST /api/personality/quiz

```jsonc
// req（作答）
{ "skip": false, "answers": [3,4,2, /* …15 ints 1–5 */], "durationMs": 42100 }
// req（主動跳過 F7/D5）
{ "skip": true }
// 200（complete / skipped 升級時——profile 帶本筆結果）
{ "profile": { "status": "complete", "oceanMeasured": { "extraversion": 58.33, "agreeableness": 41.67,
    "conscientiousness": 66.67, "emotionalStability": 75, "intellectImagination": 50 },
    "answers": [/*15*/], "createdAt": "…" } }
// 422 觸發亂答（首次）→ 前端按 code 提示重測一次
{ "error": "Careless responding suspected — retake once", "code": "CARELESS_SUSPECTED" }
// 400：skip 與 answers 互斥（皆缺或皆給 → SKIP_ANSWERS_CONFLICT）；
//      長度≠15 或值域出 1–5（VALIDATION_FAILED）；body 非 JSON（INVALID_JSON）
{ "error": "…", "code": "…" }
```

- **型別細節**：`(raw − 3) / 12 × 100 = (raw − 3) × 25/3` 為**非整數值**——`oceanMeasured` 各維 wire 用 f64 實值（不預先取整，避免捨入誤差進入 F3 門檻比較），UI 顯示時取整。`status` wire 值為 `complete` / `carelessSuspected` / `skippedPriorOnly`。`ft-schema` 的 `QuizSubmission` 為 `{ skip: bool, answers: Option<Vec<u8>>, durationMs: Option<u64> }`——**skip 是顯式旗標；omitted 欄位不等於 skip**（`{}` → 400，防漏傳 answers 的客戶端被默默記成跳過）。`durationMs` 缺失或 0 → 走 `too_fast` 亂答訊號（422 路徑），**不是** 400。

- 狀態機（**已裁決：每次提交都落庫**，狀態由資料推導、server 端權威、跨會話有效）：
  - 未觸發 → 存 `complete`
  - 觸發，且**最新一筆（不限 status）**為 `careless_suspected` **且其 `created_at` 在 5 分鐘內** → 存 `skipped_prior_only`（回 200）。謂詞是「最新一筆 ∩ 時間窗」——**不是**「視窗內存在任一 careless」（Grok 二審 R2-1：careless→重測 complete→再亂答必須重新從 422 開始，不得因視窗內舊 careless 直接升級）
  - 觸發，其餘情況 → 存 `careless_suspected`，回 422
  - 主動跳過（`skip: true`）→ 存 `skipped_prior_only`；`skip:true` 時 `answers`/`durationMs` 皆須缺省，殘留任一 → 400
  - skipped 後主動重測通過 → 存 `complete`（skipped 非永久狀態）
  - **前端防雙擊**：送出期間 `submitting=true` disable 按鈕，**所有請求出口（含 400/429/網路錯誤/200 skipped）都要清鎖**（Grok 二審 R2-17）；D1 無交易可用，跨 isolate 同毫秒的理論競態記為已知限制
  - **POST 後一律重 GET**（Grok 二審 R2-18）：POST 回的 `profile` 是「本筆」結果，UI 四態的資料源一律以 GET 讀模型為準

### GET /api/personality/me

```jsonc
// 200（無任何資料時兩欄皆 null）
{ "profile": { "status": "complete", "oceanMeasured": {/*…*/}, "answers": [/*15*/], "createdAt": "…" },
  "status": "skippedPriorOnly" }
```

- **讀模型（Grok 審後修訂）**：`profile` = **最新一筆 `complete`**（有效側寫不因後續 skip/亂答而從產品表面消失——F7 檢視權、D5「skip 不掛名下分數」的語義都指向 last complete）；`status` = **最新一筆**的狀態。**前端四態只讀頂層 `status`；`profile` 僅為 last-complete 資料包，其內部的 `profile.status` 恆為 `complete`、不參與切態**（Grok 二審 R2-13 型別陷阱）。切態表：`null`→問卷；`complete`→結果頁；`carelessSuspected`/`skippedPriorOnly`→「本次無法計分」＋重測路徑（`profile` 存在時附「查看上一次結果」入口）。含原始 15 題答案（F7）。latest 與 last-complete 兩次讀取無交易——單用戶寫入頻率下已知限制（R2-14）。

### DELETE /api/personality/me

- 刪除該 user 全部 `personality_profiles` rows（F7：不連動帳號與命盤）；**無 request body**（對齊現有 `post_empty` 慣例，DELETE body 在部分中間層相容性差）；回應形態對齊現有 routes 慣例。

錯誤代碼/欄位形態（`{error, code?}`、CORS、rate limit 標頭）對齊 `routes/` 現行實作；**本模組所有非 2xx 帶 code**——429=`RATE_LIMIT`（對齊 charts.rs 既有慣例）、400=`SKIP_ANSWERS_CONFLICT`/`VALIDATION_FAILED`/`INVALID_JSON`、500=`DB_UNAVAILABLE`/`DB_ERROR`（Grok 二審 R2-8/R2-16；前端中文文案按 code 分流）；端點命名量表中立（`/quiz`），**不沿用** rev.3 作廢稿的 `/tipi`。

## 5. 前端（crates/web）

- **問卷頁**：作答前一行用途聲明（F7 同意基礎）＋「先不測」連結（主動跳過：送 `{skip:true}` → `NotScored` 態；Grok 二審 R2-10——API 的 skip 不做 UI 就是死碼）→ 15 題單頁、五點、零命盤資訊 → 送出時 client 計時（`Date.now` 差）隨 answers 上送。422 → 頁內「偵測到作答可能不專注，請再試一次」→ 重答重送。
- **結果頁**：
  - 五維 0–100 水平條（純 HTML/CSS；切片一單向量不上雷達圖，F3 疊圖時再上）＋常模 M±SD 區間標記，常模來源標注常駐
  - 白話人格側寫：**靜態規則文案**（5 維 × 高/中/低三檔，designer 來源標注；切點用**取整後顯示分**：≥67 高、[33,67) 中、<33 低——與 UI 顯示一致，避免 66.7 顯示 67 卻走中檔的錯位）。LLM 邊界（rev.4 §1）只授權潤寫 F5 `experiment`，側寫不外包；且現行 AI provider 走 offline stub，靜態文案不受影響
  - 免責常駐；「查看原始 15 題作答」展開區；「刪除人格資料」（confirm → DELETE → 導回問卷入口）
  - 重測入口常駐但不主動邀請（180 天政策）；`skipped_prior_only` → 「本次無法計分」＋重測路徑（D5）；`careless_suspected` → 同上提示重測
- **Home**：加「人格測驗」入口卡（措辭避開「準確」），story／占卜動線不動（已裁決：只加入口不重排）。

## 7. 亂答門檻具體值（designer 判斷，集中常數，上線後依雙側 1%–15% 觸發率指標校準）

| 訊號 | 門檻 | 備註 |
|---|---|---|
| 總時長 | < 20 秒（≈1.3 秒/題） | 15 題讀題合理下限；門檻偏鬆（誤傷比漏抓傷） |
| 全同選項 | 15 題全同一值（任何值，含中間） | rev.4 原文語意；15 題全同的偶然機率 (1/5)¹⁴，誤傷可忽略 |
| 維內極端不一致 | 同維三題全距 ≥ 4 個量表點 | 原「正反題矛盾」在 IPIP-15 **每維 3 題同向**的題目結構下無正反配對可檢（rev.4 換表的未竟適配，見 K5）。性質是**端點衝突**（同維 1 與 5 並存），**非語意矛盾的等價物**——循環／中間偏作答抓不到（Grok 審指出，屬換表客觀限制）；「低變異訊號」（近全同但非整條 straight-line）列為上線後依 1%–15% 觸發率校準的候選。與 F5 `anchor_coverage` 的「全距 ≥2 → low」層級分明（≥2 僅降級覆蓋，≥4 才算亂答級） |

## 8. 資產需求（實作前置閘門）

1. **15 題繁中題目文字 — ✅ 已定案（2026-08-28 查證）**：題目全文、維度、反向題配置逐字取自李仁豪、陳怡君 (2016) **附錄 2**（原文 PDF 留檔 `assets/ipip15-lee-chen-2016.pdf`；來源：國家教育研究院 TERIC https://teric.naer.edu.tw/wSite/PDFReader?fileName=1483498721952&format=pdf ）。反向題＝新編號 10–12（情緒穩定性，5 點即 6−x），其餘 12 題正向。量表錨點（論文頁 97）：1=非常不精確、2=有些不精確、3=普通、4=有些精確、5=非常精確。
   **重要更正**：題目底本為 **Zheng 等人 (2008) 簡體版改繁**（論文附錄 2 明載），**非** IPIP 官網朱思琪 (Sih-Ci Jhu) 譯本——兩版逐字不同（例：論文「主動與別人交談」vs 朱思琪「我總是主動開始談話」），**以論文附錄 2 為權威**。題目全文見附錄 A；實作時以版本化資料檔落 repo（含維度、反向標記、來源 URL 註記）。
2. **側寫文案全文**（15 段）＋用途聲明＋常模說明——實作期第一個 PR 呈現全文由使用者審（語氣規範：描述性、無價值判斷、無「準確」）。

## 9. 驗證（TDD 形態＋整合哲學）

`.testing-rules`（integration-only、真環境）與 TDD 的調和——**分層採用**：

1. **ft-big5 純邏輯**：`#[cfg(test)]` 先寫測試再寫實作（沿用 `ft-western`/`ft-ziwei` 既有 `mod tests` 先例）：計分換算手算對照、反向翻轉、門檻邊界（19.9s/20.1s）、全同選項、矛盾判定、validate 值域。
2. **wire 契約**：ft-schema 型別先行＝契約測試；前後端共用型別，漂移編譯期死。
3. **API 整合驗證**（打生產，腳本先行會紅、部署後轉綠）：註冊測試帳號 → POST quiz（固定 15 題輸入 → 斷言手算分數）→ GET me → 亂答提交（全同選項＋超快）→ 斷言 422 → 重測通過 → 斷言 complete → 主動跳過流程 → DELETE → 斷言清空。
4. **Playwright E2E**：註冊 → /personality 問卷 → 結果頁渲染（五條＋常模標注＋免責）→ 檢視原始答案 → 刪除；0 console error。
5. CI 現行 gate（fmt --check / wasm32 build）自動涵蓋新 crate；`cargo tree -p ft-web` 不得出現 `ft-big5`。

**驗證紀錄（2026-08-28 實跑）：**

| 層 | 結果 |
|---|---|
| ft-big5 邏輯 | `cargo test -p ft-big5` **12/12** 綠（計分手算對照＋反向翻轉＋門檻邊界＋≥2 維端點衝突＋validate 值域） |
| wire 契約 | `cargo test -p ft-schema` **8/8** 綠 |
| wasm32 | ft-api / ft-web 各 **0 新增 warnings**（基線 12 legacy）；`cargo tree -p ft-web` 無 `ft-big5` |

| Playwright E2E | 對 fortnet.pages.dev（部署 `3cefb0d2`）：Home 人格測驗入口 → `/personality` 問卷 → 固定 15 題 → 結果頁五維 **100/75/50/75/0 與手算一字不差**；免責＋常模 N=738 標注＋原始作答 details＋重測/刪除全渲染；**0 console error** |
